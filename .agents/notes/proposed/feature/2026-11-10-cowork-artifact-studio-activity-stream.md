# Proposal: Cowork Artifact 工作室与活动流

Status: proposed
Date: 2026-11-10
Class: feature

Design approval: 2026-11-10（审批记录见 `docs/discussion/cowork-feature-todos.json`）。实现落地前，本记录保持 proposed。

## Problem

核心资料既包括已发生的会话/事件产物，也包括用户提前上传、尚未绑定会话的待用资料。把两者混在一个可变时间线里，会破坏活动流的追加式语义；把活动流做成可编辑资料库，又无法保留“何时发生了什么”的审计链。

同时，评审、集成、CI 相关事件在本版本不做，活动流不应继续展示这些事件。

## Proposal

拆成两个视图，共享同一批核心资料：

- 左侧 Artifact 工作室 / 资料库：
  - 可收已发生的会话/事件资料，也可上传未绑定会话的待用资料。
  - 来源筛选：全部 / 已关联会话 / 未绑定会话。
  - 支持查看、编辑、删除、下载、打开；按类型管理。
  - 核心资料类型：决策记录、工作项、重要输入（上传文档/设计稿/远程链接）、输出产物（文件类输出，不含代码仓库）。
- 右侧活动流：
  - 已发生事件的追加式记录，关联会话和事件。
  - 只读，动作只有查看 / 打开来源；不提供编辑、删除。
  - 按天分组，支持按类别筛选。
  - 不展示评审、集成、CI 事件。
- 正常 handoff 保持隐式；blocked/失败 handoff 按会话内转交规则处理。

## Alternatives considered

**A. 额外做一个独立的 Artifact 工作室页面。** 左侧资料库已经能同时容纳会话资料和未绑定上传；再开一个页面会重复同一批资料和筛选。

**B. 只做一条可变的活动流。** 活动流是已发生事件的审计记录，不能承载“提前上传、尚未绑定会话”的待用资料，也不应允许编辑历史事件。

**C. 让活动流同时承担收件箱。** 活动流只读，收件箱需要行动和状态，两者职责不同；本版本采用会话内转交，不建独立收件箱。

## Acceptance criteria

- [A1] 活动流条目显示关联会话/事件，且没有编辑、删除动作 — `source`
- [A2] Artifact 工作室可同时显示已关联会话和未绑定会话的资料，并可按来源筛选 — `source`
- [A3] 编辑、删除只发生在 Artifact 工作室；删除资料后活动流事件仍保留 — `source`
- [A4] 活动流按天分组并可分类筛选，不出现评审、集成、CI 事件 — `source`
- [A5] 代码仓库不进入资料库 — `source`
- [A6] 客户端测试覆盖来源筛选、只读活动流和资料类型 — `tests`

## Risks

- 删除资料后事件仍引用旧资料，需要“已删除”占位或审计说明。
- 未绑定上传没有会话来源，检索和归属需要额外元数据。
- 活动流只读意味着用户不能在活动流里直接处理冲突；本版本按会话内转交。

## Delivery stages

1. 资料库网格与来源筛选 — 先打通已关联/未绑定资料。
2. 活动流时间线 — 只读事件、按天分组和分类筛选。
3. 删除与引用 — 处理资料删除后的事件保留。
