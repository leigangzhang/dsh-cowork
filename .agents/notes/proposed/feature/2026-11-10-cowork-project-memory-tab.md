# Proposal: Cowork 项目记忆标签页

Status: proposed
Date: 2026-11-10
Class: feature

Design approval: 2026-11-10（审批记录见 `docs/discussion/cowork-feature-todos.json`）。实现落地前，本记录保持 proposed。

## Problem

项目记忆同时承载用户偏好、项目上下文、决策摘要、规则和技能。若不做项目级收敛，就会出现跨项目记忆、规则重复声明、决策全文和摘要混放，以及运行上下文被误当成长期记忆的问题。

## Proposal

项目记忆最大范围限定为项目级。

右栏只展示四类汇总：

- 用户记忆：偏好 / 反复要求 / 个人约束；只做项目内记忆，通过导入/导出与全局同步。
- 项目记忆：项目上下文 + 关键决策摘要；不保存决策全文。
- 规则：项目规则 / 会话规则；遵循规则唯一性，不重复声明已有规则。
- 技能：声明技能（内置）+ 用户上传技能；支持 `/slash` 和 Agent 自动调用，定义方式与 Anthropic Skills 一致。

左侧会话框位置展示选中类型的详情：

- 上下文记忆用 Markdown 文档记录“什么时候添加了什么、来源是什么”，不做时间线 UI。
- 用户记忆用卡片，规则用表格，技能用技能卡。
- 决策记录只显示摘要，并提供“全文见 Artifact 资料库”的入口。
- 运行上下文由后台管理，不出现在记忆标签页。

## Alternatives considered

**A. 跨项目共享记忆。** 工具最大范畴是项目级；跨项目共享会把权限、来源和冲突处理引入另一个维度，本版本不做。

**B. 用时间线展示上下文记忆。** 上下文需要的是可读的 Markdown 记录和来源，不是事件流；时间线会增加噪声，也会与活动流混淆。

**C. 把决策记录全文放进项目记忆。** 决策记录需要独立 review 和版本，全文归 Artifact 资料库；记忆只保留摘要和链接。

**D. 把技能当成事实记忆。** 技能是可执行资产，需要独立定义、调用和权限；与偏好/事实混放会破坏两类内容的边界。

## Acceptance criteria

- [A1] 右栏显示用户记忆、项目记忆、规则、技能四类及数量 — `source`
- [A2] 左侧选中项目上下文时以 Markdown 文档呈现添加时间和来源，不出现时间线 — `source`
- [A3] 决策摘要提供跳转 Artifact 资料库的入口，不在记忆中保存全文 — `source`
- [A4] 规则只显示项目规则/会话规则，已有规则不重复声明 — `source`
- [A5] 技能显示内置/上传类型和 `/slash`、Agent 自动调用标记 — `source`
- [A6] 运行上下文不出现在记忆标签页 — `source`
- [A7] 客户端测试覆盖四类汇总、Markdown 详情和规则唯一性 — `tests`

## Risks

- 用户记忆导入/导出需要明确的覆盖和冲突策略；本记录只定义分类。
- 规则唯一性需要来源检查，否则记忆仍可能复制已有规则。
- 自动 Review 策略和技能执行的细节仍是待定项。

## Delivery stages

1. 四类汇总与分类详情 — 先做只读展示。
2. 上下文 Markdown 与决策摘要链接 — 接入资料库入口。
3. 导入/导出与技能入口 — 打开同步和技能列表。
