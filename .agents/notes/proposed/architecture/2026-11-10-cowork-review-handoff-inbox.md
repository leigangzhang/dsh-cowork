# Proposal: Cowork 评审、handoff 与收件箱的会话内转交

Status: proposed
Date: 2026-11-10
Class: architecture

Design approval: 2026-11-10（审批记录见 `docs/discussion/cowork-feature-todos.json`）。实现落地前，本记录保持 proposed。

## Problem

四个侧边栏标签覆盖了主题、工作项、Artifact 工作室/活动流和项目记忆，但没有为评审、handoff 和“需要用户处理”的冲突建立独立对象。若再增加收件箱标签，会与主题页顶部入口、会话内消息和工作项待办重复。

本版本明确不做评审、集成和 CI 环节；handoff 正常路径应保持隐式；跨主题冲突的解决细节尚未定。

## Proposal

### 评审

- 本版本不做评审、集成、CI 闸门相关功能。
- 评审请求页只保留为讨论稿，不进入本版本 feature 待办。
- 工作项页不展示评审、合并、CI 状态。

### handoff

- 正常 handoff 隐式：只落后台文档/记忆，不占用户主视图。
- 主会话可读取 handoff，用于路由和上下文。
- `blocked` 或投递失败的 handoff 按所属会话转交：主题会话内的问题发在主题会话，主会话发一行提醒；主会话内的问题直接发在主会话。

### 收件箱

不新增独立收件箱对象，也不新增第五个标签。未覆盖的冲突/待处理统一在所属会话内转交给用户：

- 主题会话内冲突/待处理：主题会话内发行动消息，主会话发一句提醒。
- 主会话内冲突/待处理：主会话内直接发。
- 跨主题冲突：先只在主会话打印冲突并发起解决；具体展示和解决流程待定。
- 同一事件只提醒一次，处理后不再重复。
- 主题页的“需要你处理”只是入口，打开对应会话内的行动消息，不是队列。

## Alternatives considered

**A. 增加第五个「收件箱」标签。** 它会把四标签布局变成五标签，并重复主题页顶部入口和会话内行动消息；本版本选择把处理放回发生问题的会话。

**B. 把 handoff 做成 Artifact 资料库中的常规资料。** handoff 主要是机器到机器的隐式交接，正常路径不需要用户查看；暴露成常规资料会增加噪声，也会与决策记录混放。

**C. 在本版本继续做评审和集成闸门。** 用户已明确本版本不做评审、集成、CI；继续做会扩大范围并拖慢工作项/资料库设计。

## Acceptance criteria

- [A1] 不新增独立收件箱标签或收件箱对象 — `source`
- [A2] 主题会话内冲突在主题会话发行动消息，并在主会话发一行提醒 — `source`
- [A3] 主会话内冲突只在主会话发行动消息 — `source`
- [A4] 正常 handoff 不在用户界面常驻；blocked/失败 handoff 进入所属会话 — `source`
- [A5] 跨主题冲突先只在主会话打印并发起解决 — `source`
- [A6] 客户端测试覆盖会话内转交路由和去重 — `tests`

## Risks

- 用户可能漏看会话内行动消息；主会话提醒只解决主题会话的一部分可见性。
- 跨主题冲突的展示和解决细节未定，当前只确定“在主会话发起”。
- 自动 Review 策略仍未定；评审页虽然暂缓，相关决策记录 review 仍可能需要用户动作。
- 去重逻辑需要事件 id 或稳定键，否则同一冲突可能重复提醒。
