# M0：用真实宿主探针证明五项 API 风险

- Class: architecture
- Date: 2026-11-05
- Status: implemented

## Decision

- 已落地：M0 交付一个 host-only 探针插件（`cowork_probe` 工具、`/dsh-cowork/probe/{health,run,status}` 回环路由、运行时 preset `cowork-probe`），在 DSH Desktop 2.0.18 / 核心 0.2.1-rc.2 上实证 PLAN §3.2 的五项风险；证据只认 `docs/M0_PROBE_RESULT.md` 与 `.dsh-cowork/probe/runs/<runId>.json` 中的原始输出。
- 已落地：thread 的唯一创建通道是 `sessionController.create`。会话要出现在侧栏并被项目接纳，必须传 `workspaceId`；`create({cwd})` 只设置 cwd，不执行 `attachSession`（`dsh-api-session-controller/lib/index.js:756,774-786`）。
- 已落地：M0 的 preset 由 `ctx.agentPresets.register` 运行时注册（空 `plugins` 可注册、可被 `create` 选中），不写 profile；需要跨重启保留的 preset 必须由 M4 的 bundle patch 声明 `@deepseek-ai/dsh-agent-preset` 行提供。
- 已落地：构建通道把类型与运行时分开——类型来自 DSH 源码 checkout 的 `tsc -b` 声明，运行时链接指向已安装 app；`npm run build` / `npm run typecheck` 不再要求调用者设置 `DSH_CHECKOUT`。client 半边在 M0 移除，M3 重写。
- 已落地：探针只接受回环请求（`socket.remoteAddress` 与 `Host` 双检），每次 run 结束写 `last-run.json` 与 `runs/<runId>.json`，宿主重载后 `/status` 仍按文件回读。
- 已落地：PLAN 的两条前提被实测推翻——DSH 0.2.13+ 没有全局 `allowedRoots`（可写根 = 会话 cwd + `/tmp` + `os.tmpdir()`）；`patchReload` 在 web profile 与 app 中均不存在，真实热重载开关是 `dsh-hmr`。

## Consequences

- 新增约束：M1 创建 thread 必须先经 `workspaceRegistry.resolveByPath`（或 `list`）取 `workspaceId` 再传给 `create`；只传 `cwd` 的会话不会进侧栏。
- 新增约束：任何要落盘的 thread 工作区必须以该路径为会话 cwd（或先建 workspace）；不要依赖不存在的 `allowedRoots` 白名单。
- 新增约束：需要跨重启保留的 preset 只能由 bundle patch 声明；运行时 `register` 仅适用于探针和临时会话。
- 新增约束：不要把 `patchReload` 当作热重载依据；`dev_inject_plugin` 注入即时生效，正式 `install_bundle` 后需重启。
- 替代关系：取代脚手架的 daemon-loop（`src/index.ts` 的 timer/llm 循环）与 client 半边（`src/client/index.ts`、`tsdown.config.ts`）；client 在 M3 以当前 slot API 重写。
- 移除或迁移：README / AGENTS.md / docs/testing.md 的 build 说明已从「host + client / 需要 DSH_CHECKOUT」改为 host build + 自动探测；M0 文档成为五项风险的唯一证据家，PLAN 不再被当作这些 API 事实的来源。

## Testing

- AC-1: 两轮 idle 唤醒 — 已验证（`source`）：M0 文档 §1 引用 run `run-80e3683b…`；独立解压 `session-34817d4b…/session.v4.jsonl.zstd` 见两轮 `turn/start→turn/end(completed)`，assistant 文本均为 `COWORK_PROBE_WAKE_OK`。
- AC-2: create 可见并挂 workspace — 已验证（`source`）：`sessionController.list` 行 `running=false`、cwd=仓库；`workspace.sessionIds` 含该会话；文档已明示未验证 DOM 渲染。
- AC-3: preset 运行时注册与选择 — 已验证（`source`）：`agentPresets.list()` 含 `cowork-probe`；`create({agentPreset})` 返回值与会话 header 均为 `cowork-probe`。
- AC-4: 原子写可被两个会话读 — 已验证（`source`）：store 阶段两个不同 reader 会话各自读到同一 token；`writeFileAtomic` 不 fsync，目录 fsync 由探针补。
- AC-5: worktree 会话可读可写 — 已验证（`source`）：worktree 会话 header.cwd=worktree，工具日志含 `read`、`cp && cmp`、`shasum`；`git worktree list` 清理后仅主工作区。
- AC-6: 构建与仓库门禁 — 已验证（`packaging`、`tests`）：`npm run typecheck` / `build` / `check` / `test`（12 pass）/ `check:self-test`（5 个合成违规全部变红）均 exit 0。
- AC-7: 文档发布分类 — 已验证（`publication`）：`docs/publish.json` 将 `docs/M0_PROBE_RESULT.md` 归为 internal 并带理由，`npm run check` 通过。
- 未验证：侧栏真实 DOM；desktop profile；空 `plugins` preset 未跑 turn；类型 checkout 0.2.0-rc.2 与运行时 0.2.1-rc.2 的小版本漂移；官方 `install_bundle` 通道。
- 未运行项：浏览器 UI 取证、desktop profile 实测、M1 产品功能（M0 范围外）。
