# 主题页：会话与决策记录

Status: draft（design 2026-11-10；implementation not started）

## 背景

现有主题页只负责列表：按生命周期分组，点开主题进入对应会话。主题会话模型确定后，主题还要承担两件事：

- 管理决策记录。决策记录对用户可见，需要审核；全文进资料库，查看入口是活动记录。
- 做跨主题的会话交接。正常交接只落后台文档或记忆，不占用户主视图。

附件草稿给出六条流动：会话分配、事件上报、会话交接、记录提案、启动提案、归档提案。本设计把“点开一个主题之后看到什么”定下来：一个页面里左边是主题会话，右边是决策记录，六条流动各有一个固定位置。

## 设计目标

- 一个页面里同时看到会话过程和决策记录，审核时不用来回切换。
- 用户能预期每条流现在哪里出现、自己需要做什么。
- 主会话相关的内容只留一行摘要，不复制全文。
- 右侧栏窄至 378px 时仍然可用：单列显示，用切换看另一半。

## 可实现性调研

### 结论

一个页面内左右分栏可以原生实现，不需要嵌入网页。宽度不足时退回单列。

### 依据

1. 右侧栏 tab 的正文就是一个普通前端组件，可以自己排两栏。现有面板已经在宽度大于 480px 时做列表与详情分栏（`src/client/model.ts:23`，`SPLIT_WIDTH_THRESHOLD = 480`）。
2. 右栏宽度可拖动。宿主 DSH 0.2.1-rc.2 的实现里，右栏默认取窗口宽度的 45%，最小 300px，最大为窗口宽度的 70%（`@deepseek-ai/dsh-client-ui-layout` 的 `RIGHTBAR_DEFAULT_RATIO` / `RIGHTBAR_MAX_RATIO`）。窗口 1416px 时默认约 637px。
3. 右栏有全屏形态，覆盖整个窗口（Windows 上让开左侧栏），页面拿到的宽度足够放两栏。普通和全屏两种形态共用同一棵内容树，切换不丢状态；入口是面板右上角的形态按钮或 `ctx.sidebarRight.toggleFullscreen(target)`（`@deepseek-ai/dsh-client-ui-sidebar-right` 的 README 与实现）。
4. 所以取 640px 作为分界：页面宽度达到 640px 时左右分栏，低于 640px 时单列。用户拖宽侧栏或切到全屏都会跨过这个宽度。

### 备选：把 HTML 页面嵌进来

- 可行。宿主的 webserver 可以注册任意路由；DSH 自带的文档预览就用 iframe 渲染 HTML：静态模式用 `sandbox=""` 加 CSP，交互模式用 Blob 地址加 `sandbox="allow-scripts"`。
- 代价：面板数据要经 `postMessage` 转发；样式、键盘和主题色与原生页面难以完全一致；多一层调试位置。
- 用途：实现前先看效果。本设计的设计稿是一个 HTML 页面加一份 CSS，可以先嵌进 tab 里看。
- 限制：内置浏览器 tab 拒绝打开应用自身的 origin（该包 README 写明），所以不能借它，必须嵌在自己的面板里，并且不要授予 `allow-same-origin`。

### 不采用：主区域整页

`main` 槽可以注册面板，`layout.selectPanel` 也能切换，但没有找到公开的侧栏入口注册方式，这一点未核实。而且整页会替换主会话，与“左侧主会话 + 右侧栏”的既定布局冲突。

## 页面结构

```text
主题页（一个页面）
├─ 顶部：返回主会话 / 主题名 / 生命周期 / 待审核标记 / 工作项数 / 需要你处理 / 展开
├─ 左栏：主题会话
│  ├─ 会话分配（来自主会话）
│  ├─ 对话与执行步骤
│  ├─ 事件上报（一行摘要）
│  ├─ 会话交接（默认折叠成一行，阻塞时展开）
│  └─ 需要你处理的行动消息 + 回到完整会话的入口
└─ 右栏：决策记录
   ├─ 待审核提案（记录 / 启动 / 归档）
   ├─ 已处理的记录列表
   └─ 活动记录入口
```

宽度低于 640px 时，左右两栏变成单列，顶部加“会话 / 决策记录”两个切换项；“需要你处理”始终留在顶部。

## 六条流动在页面里的位置

| 流动 | 方向 | 页面位置 | 用户要做什么 | 默认可见 |
|---|---|---|---|---|
| 会话分配 | 主会话 → 主题 | 左栏第一行 | 一般不用管；需要时可退回主会话 | 可见 |
| 事件上报 | 主题 → 主会话 | 左栏一行摘要 | 需要时展开查看 | 可见 |
| 会话交接 | 主题 → 主会话或其他主题 | 左栏交接区 | 只在阻塞或失败时处理 | 折叠 |
| 记录提案 | 主题 → 决策记录 | 右栏待审核卡 | 通过，或写清原因退回 | 置顶 |
| 启动提案 | 主题 → 决策记录 | 右栏提案列表 | 通过后启动对应工作项 | 列表 |
| 归档提案 | 主题 → 决策记录 | 右栏归档卡 | 检查未完成项后归档 | 收尾时出现 |

## 交互规则

- 打开页面默认看左栏；有待审核的决策记录时，右栏的审核卡置顶，顶部显示数量。
- 点“需要你处理”定位到左栏的行动消息，不打开独立收件箱；没有待处理项时不显示这个按钮。
- 审核通过：卡片就地变成已通过，写入活动记录，全文进资料库，顶部数量减一。
- 需修改：填写要改的地方后退回主题会话；右栏保留需修改标记和原因。
- 会话交接：正常交接只留一行“已完成”；阻塞或失败时显示原因和“在主会话解决”，主会话同时留一行提醒。
- 归档：先列出未完成项。未完成的工作项、待审核的决策记录、待处理的行动消息都会让提交按钮不可用；三项清空后才能归档。归档后页面转为只读，可以重新打开。
- 窄屏：单列显示，顶部保留“需要你处理”，用“会话 / 决策记录”切换；页面的展开按钮切到全屏后恢复左右分栏。
- 键盘：沿用面板已有的快捷键，展开与退出全屏是 `Cmd/Ctrl + Alt + Enter`；tab 顺序先左栏后右栏。

设计稿按六步展示，可以点顶部步骤切换，也可以切“宽屏分栏 / 侧栏窄屏”看两种形态。审核卡上的“通过 / 需修改”和左栏行动消息可以点击；先把审核卡和行动消息处理掉，归档按钮才会可用。

1. 总览：六条流动与它们在页面中的位置。
2. 默认：左右分栏，待审核决策记录置顶。
3. 会话分配与事件上报：主会话把需求分进来，主题把进展按一行摘要报回去。
4. 决策记录提案：三类提案都在右栏出现；记录提案就地审核，启动和归档在列表与收尾卡里处理。
5. 会话交接：默认折叠成一行，展开后能看到正常交接和阻塞的交接。
6. 归档提案与收尾：检查未完成项，确认后主题变为已解决。

- 是否所有未完成项都阻塞归档；当前设计稿里工作项、待审核记录、待处理行动三项都阻塞。
- 窄屏下默认打开哪一栏；当前设计稿默认会话。
