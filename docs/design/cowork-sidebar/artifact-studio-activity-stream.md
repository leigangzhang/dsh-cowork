# Cowork Artifact 工作室与活动流设计

Status: draft（design approved 2026-11-10；implementation not started）

## 背景

核心资料有两类来源：

- 已发生的会话/事件产物；
- 用户提前上传、尚未绑定会话的待用资料。

这两个需求不能塞进同一条可变时间线：活动流需要保留“何时发生了什么”的审计链，资料库需要允许提前上传、编辑和删除。

## 设计目标

- 活动流只追加、只读，关联会话和事件。
- 资料库可管理已发生资料和未绑定上传资料。
- 两者共享同一批核心资料，但职责不同。
- 不单独做一个 Artifact 工作室页面；左侧资料库就是 Artifact 工作室。
- 本版本不展示评审、集成、CI 事件。

## 设计过程与决定

### 1. 定义拆分

| 视图 | 职责 | 可变性 |
|---|---|---|
| 活动流 | 已发生事件的时间线 | 只追加，只读 |
| Artifact 工作室 / 资料库 | 核心资料的分类管理 | 可查看、编辑、删除、上传 |

### 2. 活动流不做编辑和删除

活动流记录已经发生的事件。用户可以在资料库编辑或删除资料，但活动流中的事件仍然保留；删除后的资料以“已删除”占位或审计说明处理。

### 3. 资料库支持两类来源

- 已关联会话：来自主题会话或主会话的资料。
- 未绑定会话：用户提前上传、等待后续使用的资料。

资料库提供来源筛选：全部 / 已关联会话 / 未绑定会话。

### 4. 核心资料类型

- 决策记录
- 工作项
- 重要输入：上传文档、设计稿、远程链接
- 输出产物：文件类输出，不含代码仓库

### 5. 不做独立的 Artifact 工作室页面

左侧 Artifact 工作室已经同时容纳资料库和时间线所需的资料；右侧活动流负责时间线。再加一个独立页面会重复同一批资料和筛选。

### 6. 不做评审 / CI

本版本不展示评审、集成、CI 事件，也不做合并状态或评审请求。

## 界面结构

```text
左侧：Artifact 工作室
├─ 类型筛选 + 来源筛选
├─ 网格 / 列表
├─ 资料卡：类型、标题、来源、操作
└─ 上传未绑定资料

右侧：活动流
├─ 按天分组
├─ 类别筛选
├─ 只读事件：时间、类型、目标、来源
└─ 查看 / 打开来源
```

## 操作规则

| 资料类型 | 活动流 | 资料库 |
|---|---|---|
| 会话资料 | 只读查看 / 打开来源 | 查看、编辑、删除 |
| 未绑定上传 | 不进入活动流 | 查看、编辑、删除 |
| 文件输出 | 只读查看 / 下载 | 查看、下载、删除 |
| 远程链接 | 打开来源 | 打开、编辑元数据、删除 |

## 范围外

- 代码仓库作为核心资料。
- 评审、集成、CI 事件。
- 独立的 Artifact 工作室页面。
- 删除资料后的引用回收细节。

## 未决问题

- 资料删除后活动流事件的占位文案。
- 未绑定上传的检索和归属元数据。
