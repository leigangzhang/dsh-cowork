# Cowork 工作项：多模态交付物查看器设计

Status: draft（design approved 2026-11-10；implementation not started）

## 背景

工作项最初的 demo 以分支、提交、合并和 diff 为中心。用户明确纠正：工作项不是代码管理容器，而是用户需要查看、确认、反馈的交付物。

典型交付物：

- PLAN / Markdown 文档
- 设计稿
- 架构图
- Canvas / Excalidraw
- HTML demo、表格、文章

附件是关键图稿；批注和评论是主要协作方式。

## 设计目标

- 工作项可以在主区域打开为可阅读、可批注的查看器。
- 右栏只做列表和状态汇总，不复制主区域内容。
- 评论支持图片、文本和 Markdown 附件。
- 不把 branch、commit、merge、diff 等代码管理字段放进工作项主视图。

## 设计过程与决定

### 1. 从代码管理页改为交付物查看器

第一版工作项卡展示分支、审查、变更文件数和“合并到主分支”。用户纠正后，确定：

- 页面主区域是文档/画布/HTML 查看器；
- 右栏只展示类型、状态、评论数、附件数和更新时间；
- 代码管理操作从工作项页移除。

### 2. 工作项类型

首批类型：PLAN/Markdown、设计稿、架构图、Canvas/Excalidraw、HTML demo/表格/文章。

类型决定详情页的呈现方式：文档用阅读视图，画布用可批注画布，HTML 用隔离预览。

### 3. 工作项状态

状态只表达交付物协作状态：待查看、待确认、需反馈、进行中、已确认。

审查状态不属于工作项卡的主字段；评审/CI 本版本不做。

### 4. 评论、批注和附件

- 画布/文档上的评论使用编号 pin 定位。
- 评论可附带图片和文本/Markdown 文件。
- 附件作为关键图稿显示，不藏在二级菜单。
- 评论和附件一起归档到工作项。

### 5. 主区域与右栏分工

```text
主区域：工作项查看器
├─ 标题 / 类型 / 状态
├─ 预览 / 评论 / 版本
├─ 文档或画布 + 批注 pin
├─ 附件区
└─ 评论输入

右栏：工作项列表
├─ 类型
├─ 状态
├─ 评论数
├─ 附件数
└─ 更新时间
```

## 交互

- 从右栏选择工作项，主区域打开对应查看器。
- 文本类交付物支持用户直接编辑；保存、冲突和模型改写的处理见[多类型文件嵌入研究](work-item-artifact-embedding-research.md)。
- 在画布上点击可添加批注；评论可定位到 pin。
- 附件可预览、下载或在新窗口打开。
- 评论支持图片、文本、Markdown 上传。
- 工作项状态变化后，右栏只更新摘要，不改变主区域内容。
