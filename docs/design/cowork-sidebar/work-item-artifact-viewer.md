# Cowork 工作项：多模态交付物查看器设计

Status: draft（design draft v3，2026-11-10；待确认）

## 背景

工作项不是代码管理容器，而是用户需要查看、确认、反馈、修改的交付物。一个工作项指向项目里已有的一个或多个文件，查看器负责展示、批注、编辑和导出；右栏只做列表和状态汇总。

典型交付物：

- PLAN / Markdown 文档
- 需求说明、Doc（HTML，导入导出 docx）
- 表格（CSV/TSV，导入导出 xlsx）
- 架构图、流程图、时序图、ER 图等文本图表
- 设计稿（HTML/CSS、图片、SVG）
- 自由画布（Excalidraw）
- PDF、HTML demo、文章

## 设计目标

- 工作项在主区域打开为可阅读、可批注、可编辑的查看器。
- 文本能逐行审核；Doc 能按段落审核；画布能按元素或区域审核。
- 用户改文本和模型改文本可以同时发生，只有同一范围冲突时才加锁。
- 批注投递、模型思考和修改、回复都看得到状态，不需要刷新页面。
- 右栏只展示类型、状态、评论数、附件数、更新时间，不放代码管理字段。
- 附件、截图和模型回复的图片都归档到工作项。

## 页面结构

```text
AppFrame
├─ 主区域：工作项查看器
│  ├─ 顶部：面包屑 / 标题 / 类型 / 状态 / 操作（编辑、导出、在应用中打开）
│  ├─ 工具条：文档、版本、附件；阅读/源码；保存状态；批注开关
│  ├─ 内容区：文档 / 表格 / 画布 / PDF 预览
│  ├─ 右侧：评论栏（线程、状态、模型回复、输入）
│  └─ 底部：附件条和模型活动摘要
└─ 右栏：工作项列表
   ├─ 顶部：标签页（主题、工作项、活动记录、项目记忆）
   ├─ 筛选：全部、待确认、需反馈、进行中、待查看、已确认
   └─ 分组卡片：类型、状态、评论数、附件数、更新时间
```

右栏宽度 378px 时列表单列；查看器全屏时，评论栏改为右侧抽屉，内容区保留完整宽度。

## 类型与呈现

| 类型 | 查看 | 编辑 | 批注 |
|---|---|---|---|
| Markdown / PLAN | 阅读视图，源码行号 | CodeMirror，逐行 | 行、行范围、引用原文 |
| Doc | 富文本渲染 | TipTap 所见即所得，可切源码 | 段落、块、引用原文 |
| 表格 | 网格，支持筛选、排序 | 单元格编辑、增删行列 | 行、列、单元格 |
| 图表（架构/流程/时序/ER/类/状态/思维导图/C4） | Pele 渲染 SVG | 改 Mermaid 源码 | 行、节点、区域 |
| 设计稿（HTML/CSS） | 静态净化后内联；带脚本用沙箱 iframe | CodeMirror | 静态页到元素；交互页按坐标 |
| 设计稿（图片/SVG） | `<img>` 或净化后的内联 SVG | SVG 可改源码；位图不改 | 区域、pin、裁切截图 |
| 自由画布 | Excalidraw 内建 | Excalidraw，自动保存 | 元素、区域、pin |
| PDF | 浏览器原生或宿主预览 | 只批注，不改正文 | 先整体或按页，页内区域后置 |
| 其他 | 下载或打开原件 | 外部应用 | 整体评论 |

类型决定渲染器，不决定工作项记录结构。后台统一叫 `artifacts`，界面仍显示“工作项”。

## 状态

### 工作项状态

| 状态 | 含义 | 典型操作 |
|---|---|---|
| 待查看 | 新交付物，等用户看 | 打开预览、加批注 |
| 待确认 | 用户看过，等确认 | 确认、提修改意见 |
| 需反馈 | 用户已提意见，等模型或用户处理 | 查看回复、继续批注 |
| 进行中 | 模型或用户正在改 | 显示保存状态和锁 |
| 已确认 | 用户确认完成 | 归档、导出 |

状态只存在交付物记录里，评论和回复不重复存状态。

### 模型活动状态

批注投递后依次显示：

```text
queued（排队）→ sent（已送达）→ thinking（思考中）→ working（改文件中）→ replied（已回复）
                                      ↘ failed（失败）
                                      ↘ blocked（会话不可用）
                                      ↘ stale（基于旧版本 / 位置待确认）
```

状态出现在三个位置：批注卡、右栏工作项卡、查看器顶部的活动提示。失败和阻塞要给出原因和重试入口。

## 交互

### 打开与返回

- 从右栏工作项列表点一张卡，主区域打开查看器。
- 顶部“返回会话”回到当前主题会话；从左侧栏打开任意会话时查看器自动关闭。
- 关闭查看器不改变工作项状态，也不删除未保存的草稿；有未保存内容时先提示。

### 文本审核

- 阅读视图和源码视图共享行号；选中行或行范围后出现“批注”入口。
- 批注保存路径、起止行、引用原文、前后各一行和当前版本号。
- 评论栏按位置排序；点批注卡时文档定位到对应行，反之点行内 pin 时评论栏选中对应线程。
- 线程里显示用户批注、模型回复、修改摘要和版本号；回复可继续追问。
- 原文被模型改走后，批注重定位失败时标“位置待确认”，保留内容和回复，不猜位置。
- 已解决线程折叠成一行；不物理删除评论。

### 编辑

- 顶部“编辑”进入编辑态；文本用行号编辑器，Doc 用富文本编辑器。
- 编辑后 800ms 防抖自动保存，失焦、切换工作项、关闭查看器时立即保存。
- 保存状态固定显示：已保存 · r12 / 保存中 / 冲突。
- 用户正在编辑的行范围每 300ms 报给宿主，带 5 秒有效期。
- 模型改文件前检查目标范围：与用户编辑范围重叠就等待或拒绝，不重叠就放行。
- 保存遇到版本变化先做三方合并：改动行不重叠自动合入；重叠才弹冲突界面，提供查看差异、加载最新、保留我的。
- 编辑区顶部不放大段说明；锁和冲突只在真正发生时出现。

### 画布

- Excalidraw 内建在查看器里，工具条提供选择、手、矩形、箭头、文字、画笔、撤销、缩放。
- 用户编辑时自动保存；保存状态和版本号与文本一致。
- 批注按元素 id 或归一化区域定位；选中批注时高亮元素或区域。
- 用户正在编辑时，模型改画布会等当前保存；画布没有行概念，按整个文件锁。
- 模型改画布优先通过元素级工具，不直接改整份场景 JSON。
- 导出 PNG/SVG；导入导出对接 draw.io、ProcessOn；本地应用打开作为备用。

### Doc、表格、PDF

- Doc：富文本编辑，底部可切源码；导入 docx 转 HTML，导出 docx 或 PDF；复杂版式用本地应用打开。
- 表格：网格编辑，支持筛选和排序；筛选排序默认只是视图状态，导出可选当前视图或原始顺序；xlsx 导入导出，公式和样式不保证。
- PDF：只读加批注，不改正文；先做整体或按页评论，页内区域批注后置。

### 附件与多模态

- 附件区在首屏可见，显示文件名、类型、大小；可预览、下载、在本地应用打开。
- 用户可从评论输入框上传图片、文本或 Markdown；画布/设计稿可以圈选后裁切截图。
- 模型回复可以带图片或文本附件；附件和回复一起归档。
- 图片按魔数校验类型和大小；未知类型按下载处理。

### 右栏列表

- 标签页保持主题、工作项、活动记录、项目记忆四个。
- 工作项按状态分组：待确认、需反馈、进行中、待查看、已确认；已确认默认折叠。
- 卡片字段：类型、状态、标题、来源主题、评论数、附件数、更新时间。
- 正在投递或修改的卡片显示模型活动状态，不改变其他字段。
- 不显示 branch、commit、merge、diff 和评审/CI 状态。

### 窄屏、键盘与无障碍

- 右栏 378px 时列表单列；查看器全屏，评论从右侧抽屉打开。
- 键盘：Tab 遍历工具条和线程；Enter 发送评论；Esc 关闭浮层；行内 pin 可用键盘聚焦。
- 颜色不单独表达状态，状态同时有文字；图标按钮有可读标签。
- 所有滚动区有可见焦点样式，减少动态效果时关闭旋转动画。

### 空、加载、错误

- 空：还没有工作项时，给出“从主题页发起”和“上传文件”两个入口。
- 加载：骨架显示标题、类型和评论数，不显示假内容。
- 文件缺失：保留工作项记录和评论，标“文件缺失”，提供重新绑定文件入口。
- 投递失败：批注卡显示失败原因和重试；会话归档时标阻塞，不自动重试。

## 设计规则

- 后台记录叫 `artifacts`，界面叫“工作项”；旧的代码隔离 `workItems` 不合并。
- 评论、回复、附件是主字段；不塞进二级菜单。
- 文本状态和批注状态分开：工作项状态是协作状态，批注状态是投递状态。
- 同行才加锁，不重叠自动合并；画布整文件锁。
- 评论和回复只追加，不物理删除。
- 导出、在本地应用打开、复制文件路径是固定入口。

## 范围外

- 评审、集成、CI 闸门。
- 工作项之间的依赖和合并。
- 多人协作和权限系统。
- PDF 正文编辑。
- 复杂 Word 版式、Excel 公式和样式保真。
