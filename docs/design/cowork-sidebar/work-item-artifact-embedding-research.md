# 工作项交付物：多类型文件嵌入与编辑研究

Status: research（2026-11-10，v2；按新需求更新，结论待确认后再进设计）

## 结论

1. **位置与记录。** 查看器优先放主区域；后台记录叫 `artifacts`，界面仍叫工作项；旧的代码隔离 `workItems` 不合并，保留原样。
2. **所有文本类型都能编辑。** 文本、源码、Markdown、HTML/CSS、SVG 源码、Mermaid 源码、CSV/TSV 共用一套编辑器。选 **CodeMirror 6**：行号、区间装饰、多光标、撤销、输入法、无障碍都原生支持，和逐行批注用同一套行模型。
3. **图表用文本作为内容源。** 架构图、流程图、时序/角色交互图、ER 图、类图、状态图、思维导图、C4 统一写成 Mermaid 源码，用户和模型都改文本；预览用 **Pele**（MIT，无运行时依赖，支持 Mermaid 12.1 的全部图表类型，按类型注册可控制体积）。
4. **自由画布不在核心包里做。** Excalidraw、draw.io、ProcessOn 这类画布编辑器要么体积大，要么许可受限，要么会引入第二份内容状态。核心包只做只读预览加区域批注；真正的画布编辑交给外部工具，文件保存回项目后自动刷新。
5. **Office 与 PDF 按“交换格式”处理。** Doc 以 HTML/Markdown 为可编辑源，docx 只做导入导出；表格以 CSV/TSV 为可编辑源，xlsx 只做导入导出；PDF 只查看和批注，不在 HTML 里改正文。导出和“在本地应用打开”都要有。
6. **实时流程复用 discussion 脚本的数据模型，换掉轮询。** 保留“追加消息 + 版本号 + 作者 + 附件 + 大小限制”，改成宿主事件加一条 SSE 长连接；同一主题会话内串行并合并，跨主题并行。
7. **多模态双向。** 用户圈选或截图后上传；模型回复也可以带图片或文本附件。
8. **体积预算。** 当前包 437 KB，客户端脚本 96 KB。核心客户端建议不超过 500 KB；重组件按需加载或做成可选包；Excalidraw、tldraw、mermaid 全量、ExcelJS 都不进核心包。

## 本次确认的决定

| 决定 | 内容 |
|---|---|
| 查看器位置 | 主区域优先；右栏保留工作项列表 |
| 文本编辑 | 用户可以直接在查看器里改文本，不只有批注 |
| 后台命名 | 记录用 `artifacts`，界面上仍叫工作项 |
| 旧记录 | 代码隔离 `workItems` 与交付物记录不合并 |
| 模型回复 | 支持多模态（图片或文件附件） |
| 图表范围 | 架构图、流程图、角色交互图、ER 图等用同一机制 |
| Office / PDF | 优先在 HTML 里查看和编辑（PDF 只批注）；可导出到 WPS/Office 查看 |
| 外部工具 | 已评估：自由画布用外部工具，ProcessOn 只手动导入导出 |

## 编辑器与渲染器选型（重点）

### 选型标准

1. **和现有架构契合。** 页面内普通 React 组件，不套 iframe，不引入画布状态副本；输出能写回文件。
2. **文件是唯一内容来源。** 编辑器不能用内部私有文档模型存内容，否则模型改文件和用户改界面会变成两份内容。
3. **能逐行定位。** 行号、区间装饰、滚动定位都要有，批注和编辑共用同一套坐标。
4. **许可兼容 MIT。** MIT、Apache-2.0、BSD 可以；GPL 只能在外部程序里用，不能链接进包。
5. **体积可控。** 核心客户端不超过 500 KB；重依赖懒加载或做成可选包。
6. **维护状态。** 近期有发布、有持续维护者、有类型定义；单人低下载量的包只作备选。
7. **导出能力。** SVG、PNG、PDF、CSV、XLSX、DOCX 至少要能走通一条。

### 采用组合

- **文本和源码**：CodeMirror 6。阅读视图用宿主 `MarkdownText` 渲染，源码视图用 CodeMirror；批注以源码行号为锚点，阅读视图按同一行范围高亮。
- **图表**：Mermaid 源码（`.mmd`）加 Pele 预览。图表阶段先注册流程图、时序图、ER 图、类图、状态图、架构图六类；C4 和思维导图按需加载。体积实测后如果超预算，再减少类型或改用 `pele/lazy`。
- **表格**：自建网格编辑 CSV/TSV；xlsx 导入导出按需加载轻量库。
- **Doc**：不引入富文本编辑器。以 HTML/Markdown 为编辑源，docx 只在导入导出时转换。
- **PDF**：浏览器原生查看或跳宿主预览，只做批注。
- **自由画布**：外部工具闭环，核心包只做预览和批注。

### 自建编辑器的能力边界

- 文本编辑：完整。行号、区间装饰、撤销重做、多光标、查找替换、输入法、键盘操作都有。
- 表格：单元格级编辑，不含公式、图表、条件格式。
- 图表：源码编辑加 SVG 预览，不含鼠标拖拽布局。
- 设计稿：HTML/CSS/SVG 源码编辑，不是所见即所得画布。

这些边界是刻意的：越接近自由画布，体积和内容模型冲突越大。需要更强编辑能力时，走外部工具。

### 为什么自由画布不做内建

- **体积**：Excalidraw 入口 1.12 MB（gzip 353 KB），还有懒加载块；tldraw 1.86 MB 且商用授权。
- **内容模型**：Excalidraw/draw.io 的 JSON/XML 是画布状态，不是文本。用户拖一个框、模型改文件，就会出现两套状态，冲突处理和批注锚点都会变复杂。
- **模型编辑**：让模型直接改画布 JSON 比改 Mermaid 文本更容易出错，diff 也难读。
- **外部工具本来就更强**：draw.io Desktop（官方 Electron 构建，GPL-3.0）和 Excalidraw 网页端都能编辑本地文件；保存回项目后，文件监视负责刷新查看器。

因此自由画布的定位是：**查看器负责看、批注、导出；编辑交给外部工具。** 不追求在插件里做实时双向同步。

## 逐类型方案

| 类型 | 内容源 | 查看 | 编辑 | 批注 | 导出 / 外部编辑 |
|---|---|---|---|---|---|
| Markdown / PLAN | `.md` | 渲染视图 + 源码行号 | CodeMirror | 行、行范围、引用原文 | 导出 `.md` / `.html` / `.pdf`；docx 后置 |
| Doc | `.html` / `.md`（导入 docx 时转换） | 渲染视图 | CodeMirror | 行、范围 | 导出 `.docx` / `.pdf`；原始 docx 保留为附件 |
| 表格 | `.csv` / `.tsv`（xlsx 导入导出） | 网格 | 网格编辑 | 行、列、单元格 | 导出 `.csv` / `.xlsx` |
| 流程图 / 时序图 / ER / 类图 / 状态图 / 思维导图 / C4 / 架构图 | `.mmd` | Pele 渲染 SVG | CodeMirror 改源码 | 行、节点、区域 | 导出 `.svg` / `.png`；可复制到 ProcessOn / draw.io 继续加工 |
| 设计稿（HTML/CSS） | `.html` / `.css` | 静态页净化后内联（Shadow DOM）；带脚本的页用沙箱 iframe | CodeMirror | 静态页可到元素；交互页只按坐标 | 导出 `.html` / `.png` |
| 设计稿（图片 / SVG） | `.png` `.jpg` `.svg` | `<img>` 或净化后的内联 SVG | SVG 可改源码；位图不改 | 区域、pin、裁切截图 | 外部工具编辑后放回 |
| 自由画布 | `.excalidraw` / `.drawio` | 预览导出图 | 外部应用 | 区域、pin | draw.io Desktop / Excalidraw 网页端 / ProcessOn |
| PDF | `.pdf` | 浏览器原生或宿主预览 | 只做批注 | 先做整体或按页评论 | 用 WPS / 预览 / Office 编辑 |
| 其他 | 任意 | 下载或打开原件 | 外部应用 | 整体评论 | 下载、在本地应用打开 |

## 文本编辑与并发

### 保存协议

1. 用户编辑后 800 ms 防抖自动保存；失焦、关闭标签、切换工作项时立即保存。
2. 保存请求带 `baseVersion`（上次读到的文件版本）。
3. 宿主用 `fs.writeText` 的 `replaceIfVersion` 原子写入：版本一致就成功并返回新版本；不一致返回 409，附当前内容和版本。
4. 409 时界面给三个选择：查看差异、加载最新（丢弃本地）、用我的覆盖（明确确认后强制写入新版本）。
5. 大文件限制：可编辑文件不超过 256 KB 或 5000 行；超过则只读并提示用外部应用编辑。具体阈值需要在实现时用真实文件验证。

### 用户和模型同时改

- 用户有未保存内容时，文件被模型或外部应用改动：不覆盖编辑器内容，顶部显示“文件已更新”，提供差异和重载。
- 模型在改文件期间（已投递、未回复）：显示“模型正在修改”，仍允许用户编辑，但保存会走版本冲突流程；是否要软锁（模型处理期间禁止保存）待定。
- 批注里记录 `revision`；模型回复也带 `basedRevision`。两者不一致时标“基于旧版本”，批注位置重新计算。
- 模型改文件优先用定向替换，不整篇重写；这样冲突窗口小，diff 也能读。

### 批注锚点

- 文本锚点存：路径、起止行、引用原文、原文前后各一行、revision。
- 文件变化后重定位：先在原行附近 ±20 行找相同原文；找不到再全文找唯一匹配；仍找不到就标“位置待确认”，不猜。
- 画布锚点存归一化坐标（0–1），随缩放不变；图片批注同时存裁切图。
- 批注和回复都只追加，不物理删除；标记为已解决即可。

## 图表与画布

### 文本图表（Mermaid + Pele）

- 内容是 `.mmd` 文本，用户和模型都改文本；普通 diff 就能看改了什么。
- Pele 输出 SVG，按主题 CSS 变量着色；渲染失败时显示错误行号，保留源码可编辑。
- 导出 SVG/PNG；需要继续加工时复制到 ProcessOn、draw.io 或 Figma。
- 支持的图表：flowchart、sequence、ER、class、state、mindmap、C4、architecture、gantt、journey、timeline、pie、quadrant、gitGraph。图表阶段先开六类（含架构图），其他类型遇到时提示“暂不支持预览，可编辑源码或导出”。

### 自由画布（外部工具闭环）

1. 工作项登记 `.excalidraw`、`.drawio` 或导出的 `.svg` / `.png`。
2. 查看器显示预览图加区域批注；预览图由用户或模型另外导出；只有源文件、没有预览图时给出导出提示。
3. 点“在本地应用打开”，宿主用系统关联程序打开源文件。
4. 用户在外部应用保存后，文件监视发现变化，查看器自动刷新，批注按区域保持。
5. 没有本地程序时，提示导出文件后在 Excalidraw 网页端、draw.io 或 ProcessOn 打开，编辑完再导入。

关于 ProcessOn：

- 公开资料显示，网页嵌入需要先把图设为公开分享，再拿分享链接；这会把项目资料放到第三方云端，和本地优先、私有数据的前提冲突。
- 没有核实到可离线使用的嵌入方式或私有部署接口。
- 因此只支持手动导出、导入，不做登录、云同步或 iframe 嵌入。

## Office 与 PDF

### Doc

- 可编辑源是 `.html` 或 `.md`；编辑方式是源码编辑加渲染预览，不是 Word 式所见即所得。需要所见即所得时用本地应用。
- 导入 `.docx`：服务端用 mammoth 转 HTML，原 docx 保留为附件，避免丢原件。
- 导出 `.docx`：用 docx 库生成；docx 9.15.3 有 `./html` 子入口，但能否直接把 HTML 转 docx 未核实，原型里先测；不行就按结构生成。复杂版式会简化，导出前提示。
- 导出 `.pdf`：用浏览器打印样式导出，零依赖。
- 需要在 WPS/Office 里看原版式时，用“在本地应用打开”。

### 表格

- 可编辑源是 `.csv` / `.tsv`，用自建网格编辑。
- 导入 `.xlsx`：用轻量读取库把工作表转成网格；多工作表先只取第一个，其他表保留在附件里。
- 导出 `.xlsx`：用轻量写入库生成；不保证公式、样式、合并单元格。
- 需要完整能力时，本地应用打开 xlsx。

### PDF

- 查看：浏览器原生 PDF 查看器（用同源文件地址）或跳宿主预览；不引入 pdf.js。
- 编辑：只做批注，不做正文编辑。
- 导出：先导出原件；带批注的副本后置（需要 pdf-lib 叠加）。

### 导出与本地打开

- 下载：宿主按登记文件返回字节，带 `Content-Disposition`。
- 在本地应用打开：宿主调用 `sessionController.openWorkspacePath`（已核对这是可直接调用的服务方法），可列关联应用。
- 打开前宿主会校验路径确实映射到本机文件，不能用浏览器传来的任意路径。

## 实时反馈与并发

### 从 discussion 脚本复用和替换

复用：

- 消息模型：`author`（user/agent）、`text`、`attachments`、时间、版本号（`cowork-discussion-server.py:212-228`）。
- 限制：正文 4000 字、附件最多 5 个、单文件 5 MB、只收图片和文本、图片按魔数校验、附件 URL 只允许 `/uploads/`（`:31-37`、`:82-116`、`:119-140`）。
- 追加式记录、原子替换写文件、读时校验（`:55-66`）。

替换：

- 轮询（`cowork-discussion-watch.py:28-32` 每 2 秒查一次）改为会话事件、文件监视和 SSE 推送。
- 单进程全局锁只保护写入；不把投递模型的过程放在锁里。
- 状态从“整份 JSON 读写”改为“追加日志 + 版本号 + 事件序号”，支持断线重连。

### 投递状态

```text
用户批注 ──▶ queued ──▶ sent ──▶ thinking ──▶ working ──▶ replied
                              └──────────▶ failed / blocked / stale
```

- `queued`：已写入，等待投递。
- `sent`：宿主已接受 prompt。
- `thinking`：目标会话 `turn/start`。
- `working`：出现工具调用或文件变化。
- `replied`：回复工具带回了批注编号。
- `failed`：投递失败，可重试。
- `blocked`：会话不存在或已归档，不自动重试。
- `stale`：文件版本已经变化，回复基于旧版本，需要用户确认。

### 主题会话内：串行 + 合并

- 同一主题会话同时只允许一个在途投递；宿主对同一会话本来就是队列处理，插件不额外并发。
- 用户连续提交多条批注时，用 1.5 秒合并窗口合成一条消息，最多带 10 条批注；模型一次回复多条，减少轮次和费用。
- 合并只发生在同一工作项内；跨工作项不合并，避免批注意图混淆。
- 如果用户坚持立即打断当前轮，再考虑 `steer`；第一版不用。

### 跨主题：并行 + 上限

- 主会话一次操作可以要求多个主题的多个工作项处理批注，必须并行发送到多个会话。
- 每个会话仍然串行；全局同时投递数默认 4，可配置 1–8。
- 每个会话队列上限 50 条，每个项目待处理上限 200 条；超过时拒绝并提示。
- 主会话的工具调用立即返回投递编号，不等待模型回复；全部结束或超时后，用一条摘要事件回报主会话。
- 失败分类：会话不存在或已归档不重试；宿主拒绝或超时按 1s、4s、15s 退避重试，最多 3 次。
- 投递记录持久化；宿主重启后，未回复的投递标记为 `stale` 或重新排队，不重复创建评论。

### 事件流

- 每个项目一条 `artifact-events.jsonl`，事件带单调递增序号。
- SSE 路由按会话和工作项过滤；支持 `Last-Event-ID` 续传，心跳 15 秒。
- 事件类型：批注新增、投递状态变化、文件版本变化、回复新增、批注位置失效。
- 浏览器只重载变化的文件；滚动位置按行文本恢复，不按像素。
- EventSource 是同源带 cookie 的，但还没在真实宿主上验证；备选是 fetch 流式读取。

### 多模态

- 用户：圈选或截图在浏览器裁切，上传后存到工作项的上传目录；消息里作为图片内容发给模型。
- 模型：回复工具接受附件路径（图片或文本文件），宿主校验路径属于工作项文件或上传目录，限制类型和大小，再登记为附件。
- 附件统一走同源授权路由，未知类型一律按下载处理。

## 对比现有方法

### 嵌入方式

| 做法 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 自建 React 查看器 | 原生主题、键盘、无障碍；批注能落到行和区域；不跨 iframe | 每类文件要自己写渲染 | 采用 |
| 复用宿主文档预览 tab | 文件加载、分页、tab、刷新都是现成的 | 注册按后缀全局生效，会顶掉所有 `.md` 预览；主区域与列表分工做不出来 | 只作为“打开原件”的辅助入口 |
| 嵌 HTML 页面 | 起得快，样式独立 | 主题、键盘、无障碍、数据通道都要重做；批注与文件内容分离 | 不承载查看器 |
| 内建画布编辑器 | 编辑体验完整 | 体积、许可、第二份内容状态 | 核心包不做；可选包另议 |
| 外部桌面/网页工具 | 功能最强，零集成成本 | 要手动切换应用，不能实时双向同步 | 自由画布和 Office 采用 |
| 宿主浏览器 tab | 能打开 loopback 页面 | 拒绝打开应用自身 origin，无法注入批注 | 不用 |

### 批注定位方式

| 做法 | 常见例子 | 优点 | 问题 |
|---|---|---|---|
| 行号加原文引用 | 代码评审的行内评论 | 精确定位，模型容易照着改 | 编辑后行号漂移，要重新定位 |
| 段落或范围 | 文档协作批注 | 对用户自然 | 大段重写后锚点难保持 |
| pin 或区域 | 设计稿协作 | 适合画布，不需要文本 | 纯文本用不上 |
| 块级定位 | 笔记类产品 | 稳定 | 粒度粗，做不到逐行 |

选择：文本用行号加原文引用；画布用归一化坐标区域加裁切图；HTML 交互模式用视口坐标；所有批注带版本号。

## 风险与未核实

- **Pele 兼容性。** 模型写出的 Mermaid 语法可能超出 Pele 的解析范围；需要拿真实图表样例做兼容测试。Pele 也相对年轻，虽然背后是 Obsidian 团队、下载量高。
- **Pele 体积。** 主入口 714 KB，按类型注册后实际多大还没测；如果超过预算，需要懒加载或减少类型。
- **CodeMirror 体积。** 373 KB 是整包估算；本仓库只取需要的子集，实际值要构建后测。
- **docx 转换保真度。** mammoth 和 docx 都是简化转换，复杂 Word 文档会丢版式；需要明确“导出用于查看，不等同原稿”。
- **xlsx 保真度。** 表格第一版不保留公式、样式、合并单元格；多工作表只取第一个。需要完整能力时用本地应用打开。
- **PDF 正文编辑不可行。** 在体积和许可约束下没有合适的 HTML 内 PDF 编辑器；只能批注。
- **用户和模型同时编辑。** 版本冲突的处理体验需要真机验证；软锁是否必要还没定。
- **并发与宿主行为。** 同一会话串行、跨会话并行是设计假设，需要在真实宿主上验证会话事件顺序、限流和失败行为。
- **投递失败恢复。** 宿主重启后，已接受但未处理的 prompt 如何恢复未核实；插件只能根据会话日志和回复缺失做补偿。
- **ProcessOn 嵌入。** 公开资料显示依赖公开分享，未核实到官方私有嵌入方式；按不可嵌入处理。
- **Excalidraw 桌面端。** 官方以网页应用为主，第三方本地应用未核实维护情况；外部编辑流程依赖用户自己的工具。
- **体积上限数字。** “客户端 500 KB、包体 1.5 MB”是建议值，不是你的硬限制，需要你确认。
- **旧 `workItems`。** 已确认不合并；但代码里仍有 clone 相关记录和工具，后续要避免界面把它们当成交付物。

## 分阶段

**第一版：文本闭环**

1. `artifacts` 记录与索引摘要，评论和事件日志。
2. 主区域查看器：Markdown/HTML/源码编辑（CodeMirror）、阅读视图、行批注、评论列表、截图上传、模型回复显示。
3. 保存协议（版本校验、409 冲突、自动保存）和批注重定位。
4. 投递：会话队列、合并窗口、跨会话并发、SSE 状态推送、失败重试。
5. 模型侧：回复工具、多模态回复；同一主题内串行，主会话可并行投多个主题。

**第二版：图表与表格**

1. Mermaid 源码编辑加 Pele 预览（先六类，含架构图），导出 SVG/PNG。
2. CSV/TSV 网格编辑；xlsx 导入导出。
3. 图片/SVG 区域批注；模型回复附图。

**第三版：Office 与外部工具**

1. docx 导入导出、PDF 查看与批注。
2. “在本地应用打开”和文件监视刷新。
3. 外部画布导入流程（draw.io / Excalidraw / ProcessOn 导出文件）。
4. 需要时再评估可选画布插件（Excalidraw）。

**验收**

- 单元测试：记录校验、路径守卫、版本冲突、锚点重定位、投递状态机、事件序号。
- 浏览器端到端：真实 GUI 里编辑文本并保存、制造一次版本冲突、加批注、看到“已送达/思考中/已回复”、文件被模型修改后查看器刷新且批注仍在。
- 并发端到端：主会话一次向两个主题投递，两个会话都能收到；其中一个失败时状态可区分。
- 安全：越权路径、超大请求、跨源请求、伪造附件类型都被拒绝。
