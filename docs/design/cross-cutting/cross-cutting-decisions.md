# 评审、handoff 与收件箱的跨对象设计决策

Status: draft（design approved 2026-11-10；右侧栏收件箱已实现，评审/工作项页仍待实现）

## 背景

四个标签页覆盖主题、工作项、Artifact 工作室/活动流和项目记忆，但没有为评审、handoff 和“需要用户处理”的冲突建立独立对象。

如果再加一个收件箱标签，会和主题页顶部入口、会话内行动消息、工作项待办重复；如果让 handoff 进入资料库，又会把机器交接暴露成常规资料。

因此本文件只记录跨对象的走向，不定义具体 UI 组件。

## 评审

- 本版本不做评审、集成、CI 闸门相关功能。
- 评审请求页只保留为讨论稿，不进入本版本 feature 待办。
- 工作项页不展示评审、合并、CI 状态。
- 决策记录的 review 仍可能需要用户动作；自动 Review 策略待定。

## Handoff

- 正常 handoff 隐式：只落后台文档或记忆，不占用户主视图。
- 主会话可以读取 handoff，用于路由和上下文。
- 只有 `blocked` 或投递失败的 handoff 进入用户视图。
- 路由：
  - 主题会话内的问题：主题会话内发行动消息，主会话发一行提醒。
  - 主会话内的问题：主会话内直接发。
  - 同一事件只提醒一次，处理后不再重复。

## 收件箱

**2026-11-10 修订：** 右侧栏收件箱作为 Cowork tab 的第二列落地，旧的“不新增独立收件箱对象”结论不再适用。请求对象、通知注释、四类行动卡片和左右对话由 [topic-inbox.md](../inbox/topic-inbox.md) 定义；旧的 `.dsh-cowork/inbox.json` 仍只服务 merge-needed / review-reject / blocked / cross-topic-conflict，不是这个收件箱。

## 设计理由

### 不新增收件箱标签

四标签布局已经稳定；收件箱的职责可以落到“发生问题的会话”里。用户在主题会话中看到行动消息，比在侧栏再维护一个队列更接近处理现场。

### handoff 不做成常规资料

handoff 大部分是机器到机器的隐式交接；正常路径不需要用户操作。只有阻塞或失败才需要用户，适合走会话内转交。

### 跨主题冲突先放主会话

跨主题冲突需要跨会话视角，不适合只放在某一个主题会话里。当前只确定“在主会话打印并发起解决”，具体对比和裁决 UI 待定。

## 开放问题

- 自动 Review 策略是主题级还是全局。
- 跨主题冲突在主会话中如何展示、如何发起解决。
